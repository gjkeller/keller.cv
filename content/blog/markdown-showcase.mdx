This post is a living reference for everything Markdown can do on `keller.cv`. If a feature renders here, it'll render in any other post. If it doesn't render here, it's not supported yet — file an issue.

The blog now leans into one accent color: the same blue square that's the favicon and the endcap on every post. That blue threads through links, blockquote rules, table headers, code-block language pills, and syntax highlighting. Switch themes from the header and you'll see the palette retune to fit, but the accent stays consistent.

## Inline code and keyboard hints

Wrap a token in backticks to get a chip: `pnpm install`, `useTheme()`, or a path like `app/blog/[slug]/page.tsx`. Inline code uses the theme's accent for both the chip background and the text, so it reads as "this is a thing you'd type" without screaming for attention. Long inline tokens like `getServerSideProps` wrap inside paragraphs without breaking the line metric.

## Code blocks

Code blocks use `rehype-highlight` for tokenization and the theme's syntax palette for color. The little pill in the corner is the language tag — try switching themes and watch it follow the accent.

```ts
type Theme = {
  name: string;
  accent: string;
  isDark: boolean;
};

export function pickAccent(theme: Theme): string {
  // Returns the favicon-blue tuned for the active theme.
  return theme.isDark ? "#60A5FA" : "#2563EB";
}
```

```tsx
import { useTheme } from "@/lib/theme-context";
```

## Blockquotes

Blockquotes use the accent for the rule and a soft accent fill for the body. They work for short asides:

> The fix is documentation — but not the kind you write for humans. Agent-optimized docs.

…and for stacked paragraphs:

> Context windows degrade. The "smart zone" is somewhere around 40–60% utilization.
>
> The solution is counterintuitive: make the agent exit. Run it in a loop where each iteration starts fresh.

You can put inline `code` and [links](https://keller.cv/blog) inside a quote and they pick up the accent the same way they would in body text.

## Lists

Bulleted lists handle the usual nesting:

- The build runs on Next.js 15 with the App Router.
- MDX is parsed by `next-mdx-remote/rsc` at request time.
  - Then `remark-gfm` adds tables, strikethrough, and task lists.
  - Then `rehype-highlight` adds the `hljs-*` classes that the syntax palette colors.
- Themes are CSS custom properties; nothing here is hardcoded per mode.

Numbered lists hold their counter through paragraphs and code blocks:

1. Read the frontmatter from `content/blog/<slug>.mdx`.
2. Slice off the body and render it through MDX:

   ```ts
   const post = getBlogPost(slug);
   return <MDXContent content={post.content} />;
   ```

3. Extract `##` and `###` headings for the inline table of contents.

GitHub-flavored task lists also render — checked items pick up the accent:

- [x] Theme-aware code blocks
- [x] Accent-tinted blockquotes and tables
- [x] Per-language pill on every fenced block
- [ ] Mermaid diagrams
- [ ] Math (`$...$` and `$$...$$`)

## Tables

GFM tables get a rounded outer border, an accent-tinted header row, and zebra-striped rows that derive their tint from the theme background:

| Theme       | Accent    | Code surface | Inline chip            |
| ----------- | --------- | ------------ | ---------------------- |
| Light       | `#2563EB` | `#F1F5FB`    | `rgba(37,99,235,.08)`  |
| Warm        | `#2563EB` | `#EFE9E2`    | `rgba(37,99,235,.07)`  |
| Dark blue   | `#60A5FA` | `#172033`    | `rgba(96,165,250,.14)` |
| Dark gray   | `#60A5FA` | `#1F1F23`    | `rgba(96,165,250,.12)` |
| Midnight    | `#60A5FA` | `#0A1429`    | `rgba(96,165,250,.14)` |

Cell content can include `code`, *emphasis*, and [links](https://github.com/gjkeller/keller.cv) without breaking the layout.
